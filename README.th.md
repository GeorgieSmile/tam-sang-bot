# tam-sang-bot

> [English](README.md)

ผู้ช่วย AI รับออเดอร์ทาง LINE พร้อมหน้าจอครัวแบบหน้าเดียวสำหรับร้านอาหารตามสั่ง

ช่วงเวลาเร่งด่วน เจ้าของร้านติดทำอาหารจนตอบแชท LINE ไม่ทัน ส่วนช่วงเวลาปกติก็ยังต้องคอยตอบคำถามซ้ำ ๆ ("เปิดยัง", "หมูกรอบหมดยัง", "กี่บาท") และมานั่งแกะแชทบวกราคาเอง `tam-sang-bot` ช่วยตอบลูกค้าทันที แปลงข้อความสั่งอาหารภาษาไทยที่ไม่เป็นทางการเป็นใบออเดอร์ที่คิดราคาจากโค้ด และทำงานร่วมกับ LINE ที่เจ้าของร้านใช้อยู่แล้วโดยแทบไม่ต้องปรับตัว

---

## การทำงานของระบบ

1. **ฝั่งลูกค้า (LINE OA):** พิมพ์สั่งภาษาไทยตามปกติ (ภาษาพูด คำย่อ พิมพ์ผิด สั่งหลายกล่อง หรือส่งพิกัด LINE) บอทตอบเรื่องเปิด/ปิดร้าน เมนู ราคา และของหมดทันที ถามเพิ่มเฉพาะจุดที่กำกวมจริง แล้วส่ง **LINE Flex card** สรุปรายการและราคาที่คำนวณจากโค้ด เมื่อลูกค้ากด **ยืนยันออเดอร์** ออเดอร์จะเข้าคิวครัวทันที
2. **ฝั่งเจ้าของร้าน (สั่งงานผ่านแชท LINE):** พิมพ์ภาษาไทยส่งมาที่ LINE OA เดียวกันจากบัญชี `OWNER_LINE_USER_ID` ไม่ต้องเปิดหลังบ้านหรือจำรหัสผ่าน

   | คำสั่งที่พิมพ์ | ผลลัพธ์ |
   |---|---|
   | `หมูกรอบหมด` / `ข้าวไข่เจียวหมด` | ปิดวัตถุดิบนั้นในทุกเมนูที่ใช้ หรือปิดเฉพาะเมนูที่ระบุ |
   | `หมูกรอบมาแล้ว` / `เปิดครบ` | กลับมาเปิดขายรายการนั้น หรือล้างสถานะของหมดทั้งหมด |
   | `ยุ่ง 25 นาที` / `ยุ่ง` / `โหมดปกติ` | เปิดโหมดยุ่งเพื่อแจ้งเวลารอล่วงหน้า (5–180 นาที; ถ้าไม่ระบุใช้ 20 นาที) หรือกลับสู่โหมดปกติ |
   | `ปิดร้าน` / `เปิดร้าน` | ปิดหรือเปิดรับออเดอร์เฉพาะวันนี้ (หลังเที่ยงคืนกลับไปใช้เวลาเปิด-ปิดปกติ) |
   | `คิว` / `สรุปวันนี้` | ดูจำนวนคิวที่รอทำพร้อมลิงก์ `/kitchen` หรือสรุปยอดขายและจำนวนออเดอร์วันนี้ |
   | `เปิดแจ้งเตือน` / `ปิดแจ้งเตือน` | เปิด/ปิดการส่ง LINE push แจ้งเจ้าของร้านทุกครั้งที่มีออเดอร์ใหม่ (สำหรับร้านที่ใช้มือถือเครื่องเดียว) |
   | `หยุดบอท` / `เปิดบอท` | หยุดหรือเปิดการตอบลูกค้าอัตโนมัติชั่วคราว |

   ถ้าบัญชีเจ้าของร้านพิมพ์ข้อความอื่นที่ไม่ตรงคำสั่ง บอทจะตอบรายการคำสั่งทั้งหมดกลับไป

3. **หน้าจอครัว (`/kitchen`):** หน้าเว็บเดียวสำหรับเปิดบนมือถือหรือแท็บเล็ตข้างเตา แสดงคิวตามลำดับเวลา เน้นหมายเหตุสำคัญ (`ไม่ใส่ผัก`, `แยกน้ำ`) มีลิงก์ `เปิดแผนที่` สำหรับลูกค้าที่ปักหมุด มีแถบเปิด/ปิดร้าน โหมดยุ่ง และปุ่มกดของหมด มีเสียงเตือนออเดอร์ใหม่และกันหน้าจอดับ (Screen Wake Lock) พร้อมปุ่ม `ทำเสร็จแล้ว`, `เสร็จ + แจ้งลูกค้า`, และ `ยกเลิก`

## แนวคิดหลักในการออกแบบ

- **โค้ดคุมราคาและกติกาทั้งหมด:** LLM ทำหน้าที่เข้าใจภาษาไทยและเลือกเรียก tool เท่านั้น ส่วนราคา ตัวเลือกที่สั่งได้ ของหมด และค่าส่งคำนวณจาก `menu.yaml` และ SQLite ในโค้ด
- **ออเดอร์ปกติไม่กินโควตา LINE push:** การตอบแชทและใบยืนยันออเดอร์ใช้ `reply` token ซึ่งฟรีไม่จำกัด โควตา push (300 ข้อความ/เดือนในแพ็กเกจฟรี) จะถูกใช้เฉพาะตอนเจ้าของร้านกดยกเลิก กด `เสร็จ + แจ้งลูกค้า` หรือเปิดแจ้งเตือนเจ้าของร้านบนมือถือเครื่องเดียว
- **ลดการถามจุกจิกและไม่พูดแทรกเจ้าของร้าน:** ถ้าลูกค้าไม่ได้ระบุ ระบบใช้ค่าเริ่มต้น `เผ็ดปกติ` / `หวานปกติ` อัตโนมัติ จำที่อยู่และพิกัดเดิมของลูกค้าที่เคยสั่งส่ง ถ้าลูกค้าส่งรูป (เช่น สลิป) บอทตอบรับครั้งเดียวแล้วปล่อยให้เจ้าของร้านตรวจเองในแชท และส่งต่อให้เจ้าของร้านตอบเอง (`hand_over`) เมื่อเป็นคำทักทาย คุยเล่น ถามเรื่องแพ้อาหาร ขอเมนูที่ไม่มี หรือขอแก้ออเดอร์ที่ยืนยันแล้ว
- **เทคโนโลยีพอดีกับงาน:** Python 3.13, FastAPI, SQLite (WAL), `httpx` และ OpenAI SDK ที่เปลี่ยนผู้ให้บริการหรือโมเดลได้ผ่าน `.env` (ค่าเริ่มต้นเป็น OpenRouter)

## เริ่มต้นใช้งาน (รันในเครื่อง + ต่อ LINE OA จริง)

**สิ่งที่ต้องมี:** Python 3.13+, [`uv`](https://docs.astral.sh/uv/), คำสั่ง `sqlite3` (สำหรับสคริปต์ช่วยทดสอบ), บัญชี LINE Official Account ที่เปิด Messaging API แล้ว, API key ของ OpenRouter (หรือผู้ให้บริการที่รองรับ OpenAI API) และ `cloudflared` (`brew install cloudflared`) สำหรับเปิด HTTPS tunnel

1. **ติดตั้ง dependency:**
   ```bash
   uv sync
   ```
2. **สร้างไฟล์ `.env`:**
   ```bash
   cp .env.example .env
   ```
   กรอกค่าหลักใน `.env` *(ค่าที่ export ใน shell จะถูกใช้ก่อนค่าใน `.env`)*:
   - `KITCHEN_SECRET` — เปลี่ยนจาก `change-me-kitchen-secret` เป็นคีย์สุ่มสำหรับเปิดหน้า `/kitchen` (เช่น `openssl rand -hex 24`)
   - `LINE_CHANNEL_SECRET` และ `LINE_CHANNEL_ACCESS_TOKEN` — จาก LINE Developers Console
   - `OWNER_LINE_USER_ID` — รหัส `U...` จาก **LINE Developers Console → ช่องของคุณ → Basic settings → Your user ID** *(หรือเว้นว่างไว้ก่อนแล้วค่อยดึงในขั้นตอนที่ 5)*
   - `LLM_API_KEY` — API key ของ OpenRouter (หรือปรับ `LLM_BASE_URL` / `LLM_MODEL` ตามผู้ให้บริการที่ใช้)
   - `PAYMENT_INFO_TEXT` *(ไม่บังคับ)* — ข้อความเลขพร้อมเพย์/บัญชีแบบบรรทัดเดียวที่จะต่อท้ายใบยืนยันออเดอร์
3. **เปิดเซิร์ฟเวอร์และ tunnel:**
   ```bash
   ./scripts/dev.sh run
   ```
   เปิดอีกเทอร์มินัลแล้วรัน:
   ```bash
   cloudflared tunnel --url http://127.0.0.1:8000
   ```
   *(Quick tunnel ของ `cloudflared` จะเปลี่ยน URL ทุกครั้งที่รีสตาร์ต ต้องอัปเดต Webhook URL ใน LINE และ `PUBLIC_BASE_URL` ใหม่ทุกครั้ง หรือใช้ named tunnel แทน)*
4. **ตั้งค่า LINE OA และ `PUBLIC_BASE_URL`:**
   - ใน **LINE Developers Console → Messaging API** ใส่ Webhook URL เป็น `https://<tunnel-url>/line/webhook` กด **Verify** แล้วเปิด **Use webhook**
   - ใน **LINE OA Manager → Response settings** ปิด **Auto-reply messages** (เปิด **Chat** ไว้ตามเดิมเพื่อให้เจ้าของร้านตอบเองได้)
   - ใส่ `PUBLIC_BASE_URL=https://<tunnel-url>` ใน `.env` แล้วรีสตาร์ต `./scripts/dev.sh run` (ไม่อย่างนั้นลิงก์จากคำสั่ง `คิว` จะชี้ไปที่ `localhost`)
5. **ตั้งค่าบัญชีเจ้าของร้านและข้อควรรู้ตอนทดสอบ:**
   - ถ้าเว้น `OWNER_LINE_USER_ID` ไว้ ให้ทัก OA หนึ่งครั้งแล้วรัน `./scripts/dev.sh users` เพื่อดูรหัส `U...` นำไปใส่ใน `.env` แล้วรีสตาร์ต
   - **กรณีทดสอบด้วยมือถือเครื่องเดียว:** ทุกข้อความจาก `OWNER_LINE_USER_ID` จะถูกส่งไปฝั่งคำสั่งเจ้าของร้าน (ถ้าพิมพ์สั่งอาหารจะได้รายการคำสั่งกลับมาแทน) ถ้าอยากทดสอบฝั่งลูกค้า ให้ทักจากบัญชี LINE อื่น หรือเว้น `OWNER_LINE_USER_ID=` ว่างไว้ชั่วคราวแล้วรีสตาร์ต
6. **เปิดหน้าจอครัว:**
   เข้า `https://<tunnel-url>/kitchen?key=<KITCHEN_SECRET>` บนมือถือหรือแท็บเล็ต (ระบบจะเก็บคีย์ไว้ใน `HttpOnly` cookie ตั้งแต่ครั้งแรกที่เข้า ทำให้รีเฟรชหน้าได้โดยไม่ต้องใส่ `?key=` ซ้ำ) แล้วแตะแถบด้านบนหนึ่งครั้งเพื่อเปิดเสียงเตือนและกันหน้าจอดับ

## ปรับใช้กับร้านจริง

แก้ไฟล์ [menu.yaml](menu.yaml) ได้โดยตรงโดยไม่ต้องทำระบบหลังบ้าน:
- `shop.name`, `shop.hours` (เวลาเปิด-ปิดในโซน `Asia/Bangkok`) และ `shop.delivery` (`fee` และ `free_above`; ถ้าส่งฟรีตั้ง `fee: 0`)
- `ingredients`, `option_groups` และ `items` (ราคาตั้งต้น เนื้อสัตว์ที่เลือกได้ และชื่อเรียกอื่นที่ลูกค้าใช้)

## คำสั่งสำหรับพัฒนาและทดสอบ

```bash
./scripts/check.sh        # ตรวจ format, lint (ruff), type (mypy) และ pytest
./scripts/dev.sh reset-db # ล้างข้อมูลทดสอบใน shop.db โดยไม่ต้องหยุด uvicorn
./scripts/dev.sh users    # ดูรายการ LINE userId ที่บันทึกอยู่ใน shop.db
```

*(หมายเหตุ: `reset-db` และ `users` ต้องมีคำสั่ง `sqlite3` และฐานข้อมูลที่ถูกสร้างหลังแอปได้รับ request แรกแล้ว ถ้าเปลี่ยน `DB_PATH` ใน `.env` ให้ export `DB_PATH` ใน shell ก่อนรันคำสั่งเหล่านี้)*

ดูรายละเอียดสถาปัตยกรรม โครงสร้างตาราง SQLite และเงื่อนไขทั้งหมดเพิ่มเติมได้ที่ [SPEC.md](SPEC.md)
